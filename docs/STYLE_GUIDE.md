# Style Guide

## Writing qualities

Content should be:

- Minimal
- Technical when the subject is technical
- Readable
- Timeless (avoid slang that ages poorly)
- Evidence-based
- Structured
- Professional
- Human
- Honest

## Mechanics

- Prefer short sentences.
- Prefer concrete nouns and verbs.
- Avoid unnecessary adjectives.
- Avoid startup clichés and motivational language.
- Avoid rhetorical questions as filler.
- Use lists for scannable facts; prose for reasoning and tradeoffs.
- Use ISO dates.
- Use consistent entity titles (match `title` field).

## Numbers

- State units.
- State time windows for metrics (“p95 latency, 2024-Q3”).
- Do not round in a way that misleads; if approximate, say so.

## Names

- Companies, products, and people: official spelling
- Technologies: common canonical name (`PostgreSQL`, not `postgres` in titles; aliases can include `postgres`)

## Formatting (Markdown)

- One H1 per file (usually equals `title`)
- Hierarchical headings; do not skip levels
- Links: descriptive text, not “click here”
- Code: fenced blocks with language tags
- No emoji unless the owner explicitly adds them as content

## Words to avoid (unless evidenced)

passionate, enthusiastic, results-driven, hardworking, dynamic, innovative, game-changing, seamless, unlock, elevate, empower, thrilled, excited to share
