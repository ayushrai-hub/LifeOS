Portfolios

Many lenses on the same body of work.

There is no single portfolio here. Each page gathers projects, writing, certifications, and notes that belong to one craft. Identity emerges from what shows up on these shelves, not from a title on a banner.

  • Software Engineering ; Building useful software under real constraints.
  • Artificial Intelligence ; Applied AI systems, evaluation, and careful refusal of models when they do not help.
  • Machine Learning ; Learning from data when the problem actually needs a model.
  • Deep Learning ; Neural methods where depth is earned by the problem, not by fashion.
  • Large Language Models ; Working with LLMs as systems: routing, retrieval, evaluation, and failure modes.
  • Reinforcement Learning ; Exploring RL ideas carefully. Training claims stay empty until evidence exists.
  • Full Stack Development ; End-to-end product surfaces from data store to interface.
  • Backend Engineering ; APIs, pipelines, and services that stay understandable under load.
  • Frontend Engineering ; Interfaces that make hard workflows calm and clear.
  • Cloud Computing ; Deploying and operating systems on cloud platforms.
  • Cyber Security ; Host inventory, findings with confidence, and non-destructive collection.
  • Application Security ; Safer defaults in application design and review.
  • DevSecOps ; Security checks that live inside delivery, not beside it.
  • DevOps ; Shipping repeatedly with reproducible environments.
  • Site Reliability Engineering ; Reliability as a product of design, measurement, and restraint.
  • Systems Design ; Tradeoffs, boundaries, and the stories systems tell under stress.
  • Data Engineering ; Pipelines that keep data honest on the way to decisions.
  • Data Science ; Analysis that prefers interpretable scoring when black boxes are forbidden.
  • Research ; Questions, experiments, and notes that admit uncertainty.
  • Open Source ; Public repositories and the discipline of writing for strangers.
  • Product Engineering ; Engineering that starts from a user problem and ends in a shippable surface.
  • Product Management ; Priorities, scope, and decisions that can be explained later.
  • Project Management ; Delivery cadence, clarity, and honest status.
  • UI Engineering ; Interface implementation with accessibility and calm defaults.
  • Design ; Structure, hierarchy, and the feeling of using something carefully made.
  • Developer Tools ; CLIs, validators, and workflows that make other builders faster.
  • Automation ; Scripts and agents that remove repetition without hiding risk.
  • Business ; How products create value and how organizations decide.
  • Leadership ; Leading through execution, clarity, and shared standards.
  • Teaching ; Explaining so others can build without you in the room.
  • Writing ; Essays, notes, and documentation that outlive a chat thread.
  • Community ; Groups, events, and the work of showing up.
  • Volunteer Work ; Service projects and the people they were meant to help.
  • Fitness ; Training habits, what stuck, and what did not.
